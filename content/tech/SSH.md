## SSH 是什么

SSH（Secure Shell）是一个加密的网络传输协议。

它主要用来在不安全的网络环境里建立一条相对安全的连接，最常见的用法就是远程登录机器。

SSH 会在客户端和服务端之间建一条安全通道，后面的命令和数据都走这条通道。

## SSH 和 SSL/TLS

SSH 和 SSL/TLS 看起来有点像，都是在做加密和身份校验，但用法不太一样。

- SSL/TLS 更常见的是浏览器和服务端之间的连接
- SSH 更常见的是远程登录、远程执行命令，或者做端口转发
- SSL/TLS 一般要依赖 CA 证书体系
- SSH 通常是服务端自己生成密钥对，再把公钥信任关系分发出去
- SSL/TLS 夹在应用层和传输层之间
- SSH 更接近应用层的远程 shell 能力

简单说，SSL/TLS 更像是在保护一条 Web 或服务调用链路，SSH 更像是在安全地接管另一台机器。

## SSH 端口转发

### 本地端口转发

比如远程机器 `R` 的 `3306` 端口上有个 MySQL 服务，现在想在本地访问它。

本地端口转发就是把本地端口上的请求转到远程端口上。

```bash
ssh -L 3307:localhost:3306 root@R.IP
```

这样访问本地 `3307`，实际就会转到远程机器的 `3306`。

### 远程端口转发

通常本地主机没有公网 IP，外部机器没法直接访问本地服务。

这时候可以让远程主机暴露一个端口，再把请求转回本地。

```bash
ssh -R 3306:localhost:3307 root@R.IP
```

外部先访问远程主机的 `3306`，再由远程主机把请求转到本地的 `3307`。

### 动态转发

如果远程主机 `R` 上跑了多个服务，而且端口都不一样，本地主机 `A` 都想访问，就可以用动态转发。

```bash
ssh -D localhost:2000 root@R.IP
```

它会在本地起一个 SOCKS 代理。发到这个代理的请求，会先到远程主机，再由远程主机去访问目标服务。
