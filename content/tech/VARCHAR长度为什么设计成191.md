> `191`
<!--more-->

## 为什么经常是 191

这个值通常不是随便定的，更多是被索引长度卡出来的。

在老一点的 MySQL / InnoDB 配置里，索引前缀上限是 `767 bytes`。

如果字段用的是 `utf8mb4`，一个字符最多占 `4 bytes`，那 `767 / 4 = 191`。所以很多时候会把 `VARCHAR` 设成 `191`，尤其是这个字段还要建索引的时候。

如果是 `utf8mb3`，一个字符最多是 `3 bytes`，那对应上限大概就是 `255`。

如果是联合索引，情况还会更紧，因为这 `767 bytes` 不是只给一个字段用的，而是整段索引一起算。

## 这个问题常见在哪些版本

`191` 这个习惯，主要出现在下面这些情况：

- MySQL 5.6 以及更早的环境
- MySQL 5.7 里还在沿用老表结构的环境
- InnoDB 行格式还是 `COMPACT` 或 `REDUNDANT` 的表

因为这些场景下，索引前缀限制还是 `767 bytes`，`utf8mb4` 一上索引就很容易撞线。

从 MySQL 5.7 开始，如果用的是默认那套较新的 InnoDB 配置，情况会宽一些：

- `innodb_large_prefix` 默认开启
- `DYNAMIC` 或 `COMPRESSED` 行格式下，索引前缀上限可以到 `3072 bytes`

这时候就不一定非得写成 `191`。

所以 `191` 不是 `VARCHAR` 的通用规则，它更像是老版本或者老表结构下，为了避开 `utf8mb4 + 索引长度限制` 留下来的一个经验值。
