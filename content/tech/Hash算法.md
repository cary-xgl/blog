> 把 Hash、摘要、彩虹表这几个容易混在一起的点先记下来
<!--more-->

## Hash 的不可逆

Hash 最核心的一点就是不可逆。

原因不复杂，原始数据的可能性几乎是无限的，但 Hash 值长度是固定的。这样一来，很多不同的原始数据最后都会被压到同一个值域里。

所以从结果上看，一个 Hash 值理论上可能对应很多原始数据。也正因为这样，Hash 没法像普通函数那样再反推回原文。

## 为什么 Hash 能拿来做完整性校验

一个好的 Hash 算法，碰撞概率应该尽量低。

同时，原始数据只要有一点点变化，算出来的 Hash 值也应该明显变化。哪怕只是改了一个字符，结果也应该不一样。

所以 Hash 很适合拿来做完整性校验。不是为了还原数据，而是为了看数据有没有被动过。

## 彩虹表

Hash 本身不可逆，但这不代表它不能被撞出来。

彩虹表的思路，不是把 Hash 真正还原成原文，而是提前算出大量“可能的原文”和对应结果，用查表的方式去逼近原始输入。

它本质上还是时间和空间的交换。

### 基本思路

先约定两个函数：

- `H`：Hash 函数
- `R`：归约函数

这里的 `R` 不是把 Hash 真的还原回原文，它只是把一个 Hash 值重新变成一个“看起来像原文”的候选字符串，好让下一轮继续跑 Hash。

这样就可以形成一条链：

`原文 -> H -> Hash值 -> R -> 新字符串 -> H -> ...`

真正存表时，不需要把整条链都存下来，只存链的起点和终点就行。

这样能明显省空间。代价就是查的时候不能一步命中，要把链重新跑一遍。

### 查找时怎么做

如果要判断某个 Hash 值是不是在表里，不是直接反推，而是拿这个 Hash 继续跑 `R` 和 `H`，看它最后能不能落到某条链的终点上。

如果能落上去，再从那条链的起点重新算一遍，检查中间有没有经过这个目标值。

如果经过了，就有机会把对应原文找出来；如果没经过，说明只是碰巧撞到了终点。

### 碰撞问题

链越长，空间越省，但碰撞概率也会变高。

一旦不同链在中间撞到一起，后面就会合并成同一段路径，这样表里会出现冗余，实际覆盖到的范围反而变小。

所以这里有个平衡：

- 链短一点，空间占得多，但碰撞少
- 链长一点，空间省得多，但碰撞更容易出现

### 为什么叫彩虹表

普通做法里，一条链上每一步都用同一个 `R` 函数，这样比较容易在中间发生合并。

彩虹表的改法是，每一步都用不同的 `R` 函数。这样就算某一层碰撞了，也不容易整条链都并到一起。

这也是它比普通 Hash 链更实用的地方。

代价还是那个老问题，空间利用率更好了，但查找会更慢，时间复杂度会上去。

## MD5

`MD5` 也是一种 Hash 算法。

平时说“MD5 被解密了”，多数时候其实不是把 MD5 真解开了，而是通过穷举、字典表或者彩虹表，把原始输入撞出来了。

所以严格说，MD5 不是“可解密”，而是“可被猜中”。
