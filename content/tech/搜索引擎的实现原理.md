## 搜索引擎的核心

核心：抓取网页、建立索引、排序结果。

可以把它想成一个很大的网页图书馆。爬虫先把网页收回来，解析内容，再整理成适合检索的数据结构。用户搜索时，查的不是整个互联网，而是已经建好的索引库。拿到候选结果后，再按相关性、权威性、内容质量、时效性、体验等信号排序。

<pre class="mermaid">
flowchart LR
  A[发现 URL] --> B[爬虫抓取]
  B --> C[页面解析]
  C --> D[内容索引]
  D --> E[查询理解]
  E --> F[候选召回]
  F --> G[多阶段排序]
  G --> H[结果展示]
</pre>

## 网页抓取

### 为什么要提前抓取

互联网网页太多了。如果用户每次搜索时，搜索引擎才临时访问网页，几百毫秒内根本回不来。

所以搜索引擎会提前抓网页，提前建索引。搜索发生时，主要是在自己的索引库里查。

### 抓取限制

大多数正规爬虫会遵守抓取协议，但这不是强制权限。`robots.txt`、`meta robots`、`X-Robots-Tag` 更像是给搜索引擎看的规则。真不想让内容被访问，还是要用登录、鉴权、密钥这类保护。

- `robots.txt` 控制抓取。
- `meta robots` 和 `X-Robots-Tag` 控制索引和展示。

### robots.txt

`robots.txt` 放在网站根目录，用来告诉爬虫哪些 URL 不要抓。比如：https://example.com/robots.txt


典型写法如下, 含义是：
- 不允许 Googlebot 抓取 /admin/、不允许 Googlebot 抓取 /search、允许抓取 /search/help

```txt
User-agent: Googlebot
Disallow: /admin/
Disallow: /search
Allow: /search/help
```

常见用途：

- 限制后台路径。
- 限制站内搜索结果页。
- 限制筛选参数页。
- 避免无限 URL 被抓取。
- 节省抓取预算，减轻服务器压力。

但 `robots.txt` 不是 `noindex`。

假设写了：

```txt
User-agent: Googlebot
Disallow: /private/report.html
```

这只表示 Googlebot 不应该抓这个页面内容。可如果其他网页链接到了它：

```html
<a href="https://example.com/private/report.html">内部报告</a>
```

Google 仍然可能知道这个 URL 存在。结果就是：它知道这个地址，但没有正文、标题、meta 等内容可分析。一般不会形成正常的内容索引，但 URL 本身可能被记录，少数情况下也可能出现在搜索结果里。

所以 `robots.txt` 阻止的是抓取内容，不一定阻止 URL 被发现。

### meta robots 和 X-Robots-Tag

`meta robots` 控制页面是否允许索引，写在 HTML 的 `<head>` 里。

```html
<meta name="robots" content="noindex">
```

意思是：可以访问这个页面，但不要把它放进搜索结果。

常见写法：

```html
<meta name="robots" content="noindex">
<meta name="robots" content="nofollow">
<meta name="robots" content="noindex, nofollow">
<meta name="robots" content="nosnippet">
<meta name="robots" content="noarchive">
```

常见指令：

```text
noindex   不要索引这个页面
nofollow  不要跟踪页面上的链接
nosnippet 不要在搜索结果中显示摘要
noarchive 不显示缓存版本
```

这里有个坑：搜索引擎必须先抓到页面，才能看到 `meta robots`。如果页面已经被 `robots.txt` 挡住，爬虫就看不到页面里的 `noindex`。

`X-Robots-Tag` 是 HTTP 响应头里的 robots 指令，作用类似 `meta robots`，只是写法不一样：

```http
HTTP/1.1 200 OK
Content-Type: text/html
X-Robots-Tag: noindex
```

它适合非 HTML 文件，比如：

```text
PDF
图片
视频
CSV
Word 文档
接口返回文件
```

这些文件没有 HTML `<head>`，不能写 meta 标签。要禁止 PDF 被索引，可以在响应头里加：

```http
X-Robots-Tag: noindex
```

两类规则一起用时，要注意先后关系。如果 `robots.txt` 先挡住抓取，页面里的 `meta robots` 和响应头里的 `X-Robots-Tag` 可能根本不会被看到。最后反而变成：URL 被发现了，内容没抓到，`noindex` 也没读到。

## 索引

普通索引更像是记录每个网页包含哪些关键词：

```text
网页 A -> 包含：苹果、手机、发布会
网页 B -> 包含：苹果、股票、公司
网页 C -> 包含：香蕉、水果、苹果
```

搜索引擎会反过来建，也就是倒排索引：

```text
苹果 -> 网页 A、网页 B、网页 C
手机 -> 网页 A
股票 -> 网页 B
香蕉 -> 网页 C
```

这样查某个词时，可以直接拿到包含它的网页集合，不用把所有网页扫一遍。互联网规模下，逐篇文章扫描基本没法用。Elasticsearch 这类搜索系统底层也是这个思路。

### 页面怎么进索引

爬虫拿到 HTML 后，会先解析和清洗。大概包括：

- 解析 HTML 结构。
- 提取 `title`、`description`、heading。
- 识别正文区域。
- 过滤导航栏、页脚、广告等噪声。
- 提取页面链接。
- 处理图片 `alt`、视频信息。
- 识别结构化数据。
- 判断 canonical 主页面。
- 检测重复内容。
- 判断语言和地区。
- 分析页面主题。

这一步的重点是把正文和噪声分开。最后页面会被转成适合检索和排序的数据结构。

## 查询理解

用户输入搜索词后，搜索引擎不会只做字面匹配。它得先猜用户到底想找什么。

比如搜索“苹果”，信息量很少，可能是：

```text
苹果水果
苹果公司
iPhone
苹果股票
```

这时就要结合历史上下文、地域、时间、设备等信号。

不同查询的侧重点也不一样：

- “北京天气”偏实时查询，时间很重要。
- “Python list 去重”是技术问题，时效性没那么强。
- “附近咖啡店”偏本地生活，要看位置和周边信息。

查询理解阶段会做这些事：

```text
分词
拼写纠错
同义词扩展
实体识别
意图判断
地域判断
时效性判断
搜索类型判断
```

现代搜索不是简单的字符串匹配。它混合了关键词检索、语义理解、实体识别、链接分析和质量评估。先把查询意图看明白，后面才知道该召回什么、怎么排序。

## 排序

### 候选召回

搜索引擎不会一上来就给全网所有页面排序。它会先做候选召回，尽量别漏掉有价值的结果。召回拿到一批候选页面后，再交给后面的排序模型慢慢筛。

比如用户搜索：

```text
Redis 缓存雪崩怎么解决
```

搜索引擎可能召回这些相关内容：

```text
Redis 缓存雪崩
缓存穿透
缓存击穿
随机过期时间
限流降级
多级缓存
热点 key
缓存预热
```

### 排序信号

#### 相关性

相关性是最基础的排序因素。搜索引擎会判断页面和查询是不是真的对得上，不只是看关键词有没有出现。

它会看：

```text
关键词是否出现在标题中
关键词是否出现在正文中
关键词是否出现在小标题中
关键词之间距离是否接近
页面整体主题是否一致
是否真正回答了用户问题
是否存在同义词或语义匹配
```

比如搜索：

```text
PostgreSQL 批量更新 JSON 字段
```

高相关页面可能包含：

```text
PostgreSQL
JSON / JSONB
UPDATE
batch update
execute_batch
psycopg2
```

但一个页面如果只是堆关键词，没有解决问题，也不一定排得高。

#### 内容质量

相关不等于高质量。一个页面可以命中很多关键词，但内容很差：

```text
复制拼凑
标题党
内容空洞
广告过多
错误信息
没有实际解决方案
```

内容质量还会看：

```text
内容是否原创
解释是否完整
信息是否准确
作者或网站是否专业
是否有可信来源
页面是否对用户有实际帮助
是否过度 SEO
```

#### 链接关系和 PageRank

Google 早期一个重要创新是 PageRank。

思路很直接：如果一个页面被很多高质量页面链接，它大概率更重要。类似论文引用，一篇论文被很多权威论文引用，通常说明它有影响力。

现代搜索不会只看外链数量，还会看：

```text
链接来源网站的质量
链接页面和目标页面是否相关
锚文本内容
链接是否自然
是否存在垃圾外链
链接网络是否异常
```

数据库官方文档被大量技术博客引用，在相关查询里往往更有权威性。

反过来，买卖链接、垃圾站群制造外链，也可能被识别出来并降权。

#### 时效性

有些查询很吃时间：

```text
今天北京天气
英伟达最新财报
Chrome 最新版本问题
2026 高考分数线
某公司最新产品价格
```

这类查询里，新内容更重要。

但有些查询需要稳定、经典、权威的内容：

```text
牛顿第二定律
二叉树遍历
信息熵定义
量子化是什么意思
```

这些内容不一定越新越好。准确、权威、讲清楚更重要。

#### 用户体验

页面内容好，但体验太差，也会影响最终表现。常见问题包括：

```text
页面加载慢
移动端布局混乱
广告遮挡正文
弹窗过多
跳转异常
HTTPS 问题
恶意下载
内容不可读
```

用户体验通常不是唯一决定因素。但在内容质量和相关性接近时，体验更好的页面更占优势。

#### 上下文和个性化

同一个关键词，不同用户搜出来的结果可能不同。影响因素包括：

```text
用户所在地区
搜索语言
设备类型
当前时间
搜索历史
安全搜索设置
用户意图判断
```

比如搜索：

```text
football
```

在美国可能更偏向美式橄榄球，在英国可能更偏向足球。

最后看到的搜索结果，就是这些信号一起作用后的结果。
