## 代理是什么

代理本质上就是中间加了一层。

请求本来是客户端直接发给服务端，现在变成先发给代理，再由代理转给真正的目标。响应回来时，也是先回到代理，再由代理转给客户端。

所以代理干的事，说白了就是代收请求、代发请求、代收响应、代发响应。

## 正向代理和反向代理的区别

正向代理和反向代理，做的事情其实差不多，都是中间帮忙转一次。区别主要不在“做了什么”，而在“代理的是哪一边”。

### 正向代理

正向代理代理的是客户端。

客户端本来访问不了目标服务，或者不方便直接访问目标服务，就先把请求发给代理，再由代理替客户端去访问真正的服务端。

可以粗看成这样：

```text
Client -> Forward Proxy -> Server
```

这个时候：

- client 知道 proxy 的存在
- server 不一定知道真正的 client 是谁
- proxy 更像是站在客户端这一边

比较典型的理解方式是：

- 帮客户端绕过访问限制
- 帮客户端隐藏真实来源
- 帮客户端统一往外发请求

所以正向代理里，server 看到的通常是代理，不是最原始的 client。

### 反向代理

反向代理代理的是服务端。

客户端以为自己在直接访问某个服务，实际上请求先到了代理，再由代理把请求转发给后面的某台真实服务器。

可以粗看成这样：

```text
Client -> Reverse Proxy -> Server
```

这个时候：

- client 知道自己在访问一个地址，但通常不知道后面具体是哪台 server
- server 知道 proxy 的存在
- proxy 更像是站在服务端这一边

反向代理常见的用途：

- 负载均衡
- 隐藏后端真实服务
- 做统一入口
- 做 HTTPS 终止、限流、缓存这类事情

所以反向代理里，client 看到的是代理暴露出来的地址，后面的真实服务通常是被藏起来的。


## Nginx 为什么经常和反向代理放在一起说

因为 Nginx 最常见的用法之一，就是做反向代理。

比如一个请求先打到 Nginx，再由 Nginx 根据域名、路径、负载情况，把请求转到不同的后端服务：

```text
Client -> Nginx -> App1 / App2 / App3
```

所以平时一提到 Nginx，很多时候默认讨论的就是反向代理、负载均衡、静态资源分发这些场景。
